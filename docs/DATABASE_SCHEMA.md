# Database Schema

**Scope:** this documents the *actual* persistence layer as implemented, verified against
`database/psx_terminal.db` and `app/core/sqlite_database.py` on 2026-07-20. It is not aspirational.

The system stores data in three places, all on local disk:
1. **SQLite** — `database/psx_terminal.db` (the primary store).
2. **CSV exports** — `database/psx_history_clean.csv` (full history) and per-run report CSVs.
3. **State/CSV files** — portfolio, backtesting, and learning state under `database/`.

There is **no database server, no ORM, and no migration framework**. Schema is created imperatively by
`initialize_database()` in `app/core/sqlite_database.py`.

---

## SQLite: `database/psx_terminal.db`

Current size ≈ 194 MB. As of 2026-07-20: **905,195 rows, 2,457 distinct trading dates
(2016-08-01 → 2026-07-13), 985 distinct symbols.**

### Table: `daily_prices`

The single data table. One row per (trading date, symbol). End-of-day OHLCV plus a few
derived fields computed by the parser.

| Column | Type | Null | Notes |
|---|---|---|---|
| `id` | INTEGER | — | PK, autoincrement |
| `date` | TEXT | NOT NULL | Trading date as `DDMMMYYYY`, e.g. `13JUL2026` |
| `symbol` | TEXT | NOT NULL | Uppercased ticker, e.g. `LUCK` |
| `code` | INTEGER | nullable | PSX sector/board code; `NULL` when blank (bonds/ETFs) |
| `company` | TEXT | nullable | Company name as printed in the source file |
| `open` | REAL | nullable | Open price |
| `high` | REAL | nullable | High price |
| `low` | REAL | nullable | Low price |
| `close` | REAL | nullable | Close price |
| `volume` | INTEGER | nullable | Shares traded |
| `prev_close` | REAL | nullable | Last day close price (LDCP) from the source |
| `date_parsed` | TEXT | nullable | ISO-ish parsed date, used for chronological sort/index |
| `change` | REAL | nullable | `close - prev_close` (derived by parser) |
| `change_pct` | REAL | nullable | `change / prev_close * 100` (derived) |
| `close_position` | REAL | nullable | Where close sits in the day range, 0–100 (derived) |

**Constraints & indexes:**
- `UNIQUE(date, symbol)` — writes use `INSERT OR REPLACE`, so re-importing a day is idempotent.
- `idx_daily_symbol_date` on `(symbol, date_parsed)` — per-symbol history lookups.
- `idx_daily_date` on `(date)` — single-day snapshot lookups.

**Important storage note:** `date` is `DDMMMYYYY` **text**. `MAX(date)` is therefore unsafe (it compares
alphabetically). `main.py`'s `detect_sqlite_latest_date()` reads distinct dates and parses them in Python
to find the true chronological maximum. Any new query that needs "the latest date" must do the same, or
use `date_parsed`.

### Table: `sqlite_sequence`
SQLite-internal autoincrement bookkeeping. Not application data.

### Writer
`save_daily_prices(df)` in `app/core/sqlite_database.py` performs row-by-row `INSERT OR REPLACE`.
(Known performance limitation for bulk/replay work — see ROADMAP F1.4.)

## CSV: `database/psx_history_clean.csv`

The full cleaned history, kept **in sync with `daily_prices`** — same 905,195 rows / 2,457 dates.
Regenerated by `prepare_history_v2()` (`app/core/history_engine_v2.py`) which adds derived history-quality
columns on top of the `daily_prices` columns:

- `history_days_available` — count of rows for the symbol
- `history_row_number` — running index within the symbol
- `history_quality` — `POOR`/`SHORT`/`MEDIUM`/`GOOD`/`EXCELLENT` by days available

`run_backtest_v1` reads this file. `config.HISTORY_CSV` points at it (repointed from the stale 5-day
`psx_history.csv` during ROADMAP F0.4).

> Historical note: `database/psx_history.csv`, `_backup.csv`, `_old.csv` are stale 5-day snapshots
> (2026-06-30 → 07-06) left from earlier development. They are **not** the full history. Do not read them.

## Other on-disk state under `database/`

These are CSV/JSON files, not SQL tables. Each is owned by the engine named.

| Path | Owner / purpose |
|---|---|
| `database/backtesting/signal_history.csv` | Recorded signals for backtest evaluation. **Currently 4 rows** — the rule engine is unvalidated until historical replay (ROADMAP F1.1). |
| `database/portfolio/` | Trade lifecycle state: `open_positions.csv`, `closed_positions.csv`, ready-to-buy queue. Owned by trade-lifecycle / order-execution engines. |
| `database/strategy_learning/` | Self-learning weight state from `strategy_optimizer_self_learning_v2`. |
| `database/fundamentals/` | Real fundamentals ingestion target. **Empty by design** — fabricated data was quarantined (ROADMAP F0.1); real data lands here provenance-tagged (F3.3). |
| `database/master/`, `database/company_directory/`, `database/psx_intelligence/` | Company/sector reference metadata (names, sectors, industries). Descriptive, seed-sourced. |
| `database/historical_files/{2016..2026}/` | Raw EOD source archive (zip/gzip `.Z`), one file per trading day. The system-of-record inputs. |
| `database/backups/` | Timestamped DB/CSV backups taken before destructive operations. |
